# 도시 블록 중심 환경 재구성

## 방향과 변경

사용자가 지적한 문제는 물체 수 부족보다 건물/거리와 상관없이 나무·화분이 흩어진 배치였다. 앞서 추가한 density_props134개를 전부 걷어내고 건물 용도에 맞춘 도시 소품36개로 교체했다. 기존 props37개와 건물38개는 유지했다.

- 무인 택배함12개: 공동 주택·상점의 공용 시설.
- 전기 설비함19개: 건물 측면·도로변 설비 공간.
- 배송 상자 팔레트5개: 상점/배달소 주변 작업 공간.
- 추가한 나무60개·화분48개를 포함한 흩뿌리기 배치는 제거했다. 원래 나무12개·화분4개는 유지했다.
- 전체 소품은171개에서73개로 줄었다. 기존 녹지 객체를 새로 복제하지 않는다.
- 건물 주변에43개 표시용 포장 면을 정의해 거리/건물 사이 공간을 연결했다. 서로 겹치는 면은 기존 합침 방식으로 처리한다. 특히 서쪽 주택 열, 출발지 상업 블록, 북쪽 건물 열을 연속 포장으로 연결한다.
- 출발지에도 도로변 택배함(926,698), 설비함(934,790), 배달소 옆 팔레트(920,336)를 배치했다. 택배함은 이 좁은 구간에서만72×42로 표시한다.

도시 블록의 바탕 포장 → 기존 마당/작업 공간 → 실제 진입부 순서로 합성한다. 배송 공간은 단색 포장만 이어 주고 강한 줄눈/장식은 넣지 않는다. 건물 위치나 도로 연결을 바꾸지는 않았다. 타이틀의 긴 정면이나 시점을 복사하지 않고 현재 탑다운을 유지했다.

[생성 지시 기록](generation.md). 내장 image_gen 도구로 새 투명 PNG3종을 제작했으며 기존 파일은 보존했다.

모두 assets/images/title_match_v2에 저장했다. frames.json에 투명 여백/외곽 기준을 추가하고 기존 load_compact_image에 연결했다. 초기화 시 한 번 준비하고 종류별 공유·최근접 출력·화면 밖 생략을 유지한다. 새 자산 실패 시 기존 우편함/분리수거함/화분 이미지로 폴백하도록 연결했다. 폴백 화면의 최종 적합성은 수동 확인이 필요하다.

추가 GPU RGBA 예상은53,504바이트(약52.25KiB)다. 실제 GPU/프레임 사용량은 미측정이다. PNG 압축 크기와 GPU 크기는 다르다.

## 기능과 배치

도로/보도/진입로와 표시/충돌 외곽 간 여유, 수령/배송 구역, 가까운 도로까지의 접근 통로, 출발/주차 공간을 피하는 조건으로 배치 데이터를 준비했다. 공터 전역에 무작위로 뿌리는 방식 대신 건물마다 종류와 용도를 정하고 주변에서 자리를 잡는다.

기존 건물·소품의 위치/표시 크기/충돌과 배송 구역·입력·차량·고객·HUD는 유지했다. 제거한 추가 소품의 충돌도 함께 제거되고 새36개에는 표시와 맞춘 충돌이 등록된다. 새 지면을 실제 도로 판정에 추가하지 않는다. 택배함/설비함/팔레트는 환경 소품이며 새 상호작용 기능은 없다.

## 수동 테스트 정책

사용자 지시에 따라 **게임 실행·자동 테스트·실행 화면 캡처·커밋은 하지 않았다**. 실행 후 확인해야 할 사항을 아래에 남긴다. 이미지는 자산 자체를 확인했지만 게임 안 크기·겹침·입구 연결은 미확인이다.

지면 변경 때문에 사전 생성 캐시25개는 오프라인 자산 빌드로 준비했다. 해당 작업은 SDL 창/렌더러 업로드/게임 루프/입력을 사용하지 않는 CPU 지면 자산 생성이며 실행 테스트가 아니다. 생성물은739,550바이트(이전657,520바이트)다. 실제 첫 시작의 캐시 재사용/시간은 미측정이고 수동 확인해야 한다.

## 수정 파일

- data/maps/sample_map.json: 도시 포장43면과 고정 소품36개.
- game/world/start_scene_art.py: 신규 자산3종의 경로·준비 크기.
- game/world/road_map.py: 신규 소품 실패 시 기존 이미지 폴백.
- game/world/road_finish.py: 도시 바탕 포장을 기존 마당보다 먼저 합성.
- game/world/neighborhood_finish.py: 도시 바탕의 배송 구역은 무늬 없는 포장으로 연결.
- assets/images/title_match_v2: 신규 PNG3개와 frames.json.
- assets/ground/title_match_v2: 갱신한 오프라인 지면25개와 manifest.
- 이 폴더의 결과/생성 기록. 기존 Python 캐시 변경은 건드리지 않았다.

## 수동 테스트

1. 타이틀에서 시작해 콘솔의 지면 캐시25/25 재사용과 첫 진입/재시작 대기를 확인한다.
2. 출발지 도로변 택배함·설비함·팔레트가 적절한 크기와 방향으로 표시되는지 확인한다. 신규 소품의 투명 여백·접지·폴백 메시지도 확인한다.
3. 출발지→파란 주택→북쪽 상점→동쪽 상점→북쪽 건물 열을 이동하며 녹지 흩뿌리기가 줄고 포장/건물/설비가 하나의 블록으로 읽히는지 확인한다.
4. 수령 전후·임박·지각·완료에서 고객/!·조작 안내를 가리지 않는지, 새 포장 아래에 부자연스러운 잔디 구멍이나 경계가 남지 않는지 확인한다.
5. 물체와 실제 충돌이 맞고 배송/접근 통로·주차 공간을 막지 않는지 확인한다.
6. 화면 모드별 가독성과 프레임 체감을 확인한다. 기존 배포 EXE는 별도 재빌드 전까지 이번 소스 변경이 반영되지 않는다.
