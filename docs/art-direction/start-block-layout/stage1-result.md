# 출발지 공간 구성 1단계 결과

2026-11-28. 타이틀 title_city_v1.png와 현재 실제 플레이 화면·맵·지면 합성 구조를 확인하고 적용했다. 커밋하지 않았다.

## 범위와 구성

작업 범위는 **x0~1200, y0~1060**이다. 배달소(750,150), 카페(450,150), 왼쪽 주택3개(150,150/450/750), 북쪽 주택(750,900)을 포함한다. 도로 사이 넓은 잔디와 단독으로 놓였던 생활 소품을 작은 용도별 공간으로 묶었다.

| 공간 | 좌표/구성 |
|---|---|
| 왼쪽 주택 마당 | (18,24)~(286,312), (18,346)~(284,578), (26,646)~(276,858)의 크림색 포장. 건물 위치/여백 유지 |
| 카페 마당 | (302,24)~(586,294)의 차분한 벽돌 포장. 기존 배송 대기 여백은 보호 |
| 배달소 주변 | (590,12)~(956,302)의 낮은 대비 작업 바닥. 기존 수령 진입로와 입구 유지 |
| 주차 바닥선 | 카페와 배달소 사이 x544~584, y110~174 / y184~248. 소형2칸, 차량/차단물 추가 없음 |
| 벤치 휴식 공간 | (530,526)~(804,682)의 포장으로 벤치(630,580)·분리수거함(700,580)·화분(570,650)을 연결 |
| 나무 주변 | 짧은 포장 연결과 (838,538)~(962,668)의 낮은 녹지 바닥. 기존 나무의 위치/충돌 유지 |
| 북쪽 주택 | (602,800)~(898,1010)의 작은 앞마당과 기존 문턱·진입부를 함께 사용 |
| 가장자리 녹지 | 카페/배달소 측면과 휴식 공간 뒤에 불규칙 간격의 낮은 녹지 면. 담장·새 화단 객체 없음 |

기존 소품은 모두 충돌이 있어 한 개도 이동/삭제하지 않았다. 우편함(620,330)은 기존 진입 포장에 남기고 배달소 작업 바닥과 연결했다. 원본/v1/v2 PNG는 수정하지 않았고 기존 자산을 재사용했다. 바닥 표현만으로 용도를 구분할 수 있어 새 비트맵 제작이나 장식 객체는 필요하지 않았다.

## 구현과 보호

- sample_map.json의 road_finish.neighborhood에 표시 전용 범위/재질/주차선을 정의했다. 새로운 도로/충돌/배송 데이터가 아니다.
- neighborhood_finish.py는 초기화 시 기존 RoadFinish RGBA에만 합성한다. 월드2px 기준, 낮은 대비 포장과 짧은 가장자리 혼합을 사용한다.
- 도로 마스크·기존 보도·출발 위치/수령/배송 주변 quiet 마스크는 덮지 않는다. 문턱/기존 진입부는 그 뒤에 원래 순서로 합성한다.
- 건물·고객·차량·HUD·입력 조건·화물 규칙을 바꾸지 않았다. 새 애니메이션/보이지 않는 충돌도 없다.
- 프레임당 생성/파일 로딩/추가 개별 장식 출력 없이 기존 지면 캐시와 화면 밖 생략을 재사용한다.

1280×720 실제 SDL 렌더링에서 캡처했다. 난수 시드를 맞추고 같은 초기 수령 대기 상태·카메라를 사용했다. 카메라 추적 중심은 출발(750,450), 남쪽(600,360), 북쪽(600,800)이다. 출발/남쪽 이미지에서 일부 건물 하단은 기존 HUD에 가려진다. HUD 영역을 바꿔 과장된 비교를 만들지 않았다.

첫 시안에서는 배달소 앞 주차선이 지붕에 가려져, 최종본에서 카페·배달소 사이의 보이는 틈으로 옮겼다. 확인한 화면에서는 도로와 수령 안내가 유지되며, 벤치/나무 주변이 빈 잔디 대신 휴식 공간으로 읽힌다. 공간의 최종 미술 만족도와 장시간 주행 체감은 사용자 확인이 필요하다.

## 실제 검증

- py -3.13 -B -m unittest discover -s tests -q: **30개 통과**(기존26개 + 새 공간 구성4개).
- 새 검사: 범위 밖 픽셀 유지, 도로/보도/상호작용 마스크 보호, 알파 유지, 설정 없음 시 출력 불변.
- 기존 HEAD 맵과 비교해 neighborhood 설정을 제외한 모든 데이터가 동일함을 확인했다. 건물/소품 위치·크기·충돌·도로·배송 구역 변경 없음.
- 기존 사전 생성 지면25개와 새 RGBA를 비교해 작업 범위 밖 픽셀이 모두 동일함을 확인했다. 실제 픽셀이 달라진 캐시는3개다.
- 실제 타이틀 시작 전환 예약·SDL 지면25개 준비·갱신·그리기·종료/재초기화가 통과했다. 사용자의 다른 창에 입력을 주지 않도록 숨긴 실제 SDL 창과 렌더러를 사용했다.
- 기존 Python 캐시는 건드리지 않았고 테스트는 -B로 실행했다.

## 캐시·성능

지면 소스/설정이 바뀌었으므로 캐시25개를 새 해시로 다시 생성해 assets/ground/title_match_v2에 교체했다. 바뀌지 않은 구역은 픽셀을 비교해 보존을 확인했다. 오래된 해시 파일을 함께 상주시키지 않는다. 원본 이미지 자산은 그대로다.

| 항목 | 실측/계산 |
|---|---|
| 개선 전 플레이 init | 첫0.588초, 재시작0.600초 |
| 최종 플레이 init | 첫**0.541초**, 재시작**0.551초** |
| 최종 지면 준비 | 첫0.11초, 재시작0.10초 |
| 캐시 재사용 | 두 번 모두25/25, 재생성0 |
| 동봉 압축 캐시 실제 크기 |642,899바이트(약627.8KiB), 이전614,186바이트 대비+28,713바이트 |
| 추가 GPU 텍스처/출력 |0개 / 프레임당0회(코드 기준) |

시간은 로컬 캐시가 비어 있는 별도 프로세스의 개별 측정이며 평균/FPS가 아니다. Python 실행·타이틀 대기를 제외한 play_mode.init 시간이다. 이번 작업 중 강제로 캐시를 다시 만드는 개발용 생성에는16.831초가 걸렸지만, 이 결과를 동봉해 실제 첫 시작에서는 다시 합성하지 않는다. 배포 EXE는 재빌드하지 않았다.

## 수정 파일

- data/maps/sample_map.json: 출발지 표시 전용 공간 설정.
- game/world/neighborhood_finish.py: 초기화 합성.
- game/world/road_finish.py: 기존 보도 마스크 재사용/합성 연결.
- game/world/ground_cache.py: 새 합성 소스의 캐시 무효화 반영.
- assets/ground/title_match_v2: 갱신한25개 캐시와 manifest.
- tests/test_neighborhood_finish.py: 보호 영역 회귀 검사.
- 이 문서와 전후 캡처/비교 SVG.

## 남은 수동 확인

1. 실제 창에서 출발→카페/배달소 접근→북쪽 주택으로 주행하며 바닥이 장애물처럼 느껴지지 않는지 확인한다.
2. 카페가 배송지로 선정된 경우와 북쪽 주택 배송 시 고객/!·입력 안내가 가려지지 않는지 확인한다.
3. 주차선·녹지 가장자리와 기존 충돌 있는 소품의 가독성을 확인한다.
4. 화면 모드별 가독성·긴 배송 진행·배포 EXE는 미확인이다.

## 2단계 범위

주요 배송 구역2~3곳을 공간 단위로 묶어 확장한다. 출발지 표현을 복제해 모두 같은 광장으로 만들지 말고 주택은 작은 마당, 상점은 앞 포장/작업 공간처럼 건물 용도를 반영한다. 기존 충돌/도로/배송 데이터는 유지하고 새 표시 지면과 사전 생성 캐시만 확장한다. 대상 좌표를 먼저 선정하고 실제 화면·시작 시간을 함께 검증한다.
