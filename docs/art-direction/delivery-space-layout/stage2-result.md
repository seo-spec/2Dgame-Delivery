## 공간 구성

- 파란 주택: 크림색의 작은 마당과 좌우/뒤쪽 낮은 녹지 면으로 집 주변을 정리했다. 주차장이나 상점 작업 바닥을 복제하지 않았다.
- 북쪽 상점: 벽돌 앞 포장에 차분한 옆 작업 바닥을 연결하고, 기존 나무 아래 녹지와 이었다. 새 나무·차량·상자·주차선은 추가하지 않았다.
- 동쪽 상점: 상점 주변 작업 바닥과 정류장 쪽 공용 포장을 구분했다. 떨어져 있던 두 우편함과 분리수거함이 같은 앞마당에 놓이도록 지면을 연결했다.
- 기존 충돌 소품은 전부 그대로 유지했다. 새 장식/보이지 않는 충돌 없이 바닥만 합성했으며 원본/v1/v2 이미지는 수정하지 않았다.
- 모든 공간이 같은 광장이 되지 않도록 주택은 좁은 녹지 마당, 북쪽 상점은 벽돌+작업 공간, 동쪽 상점은 서비스 마당+정류장 포장으로 구분했다.

## 구현

sample_map.json의 road_finish.neighborhood는 출발지 원본 설정으로 유지하고, 별도 neighborhoods 목록에 대상3개를 정의했다. RoadFinish가 두 설정을 순서대로 기존 재질/마스크에 초기 합성한다. neighborhood_finish.py의 기존 재질·2px 도트·낮은 가장자리 혼합을 그대로 재사용한다.

도로·보도·상호작용 quiet 마스크를 덮지 않고 기존 진입부를 원래 순서로 합성한다. 새 개별 오브젝트/텍스처/프레임당 출력은 추가하지 않았다. 화면 밖 출력 생략과 원본 폴백, 사전 생성 캐시 경로를 유지한다. 차량·고객·HUD·규칙·새 애니메이션은 변경하지 않았다.

## 실제 전후 화면

- [수령 후 고객·느낌표·차량 비교](comparison-active.svg)

1280×720 실제 SDL 렌더링 캡처다. 난수 시드를 고정하고 테스트 도구에서 대상3개를 배송지로 선정해 양쪽 조건을 맞췄다. 이 설정은 테스트 프로세스에만 적용했고 실제 게임의 무작위 선정 코드는 바꾸지 않았다.

수령 전에는 고객/목적지 표시가 숨겨진 상태를, 수령 후에는 기존 수령 처리로 화물5개를 적재한 뒤 고객과 느낌표·오토바이·배송 안내를 함께 확인했다. 수령 후 비교는 같은 플레이어 위치와 카메라(건물 중심에서 남쪽40px)를 사용했다. 확인한 세 화면에서 도로·배송 공간은 유지됐고 고객/!가 새 포장에 가려지지 않았다.

테스트는 사용자 입력을 주입하지 않는 숨긴 실제 SDL 창에서 수행했다. SDL_RenderReadPixels 캡처를 직접 확인했으며 모의 렌더러나 생성 시안이 아니다. 장시간 실제 주행과 모든 기분/완료 상태까지 검증한 것은 아니다.

## 검증 결과

- 자동 검사: py -3.13 -B -m unittest discover -s tests -q — **30개 통과**.
- 추가 비교 도구로 기존 HEAD 맵에서 neighborhoods만 제외하면 모든 데이터가 동일함을 확인했다. 출발지 설정·건물·소품·도로·충돌·배송 구역 변경 없음.
- 기존/신규 지면25개의 RGBA를 비교해 세 범위 밖 픽셀이 모두 동일함을 확인했다. 실제 픽셀이 달라진 캐시는5개다.
- 출발지 실제 캡처 PNG의 SHA-256도 전후 동일했다.
- 실제 SDL 초기화/업로드·갱신·그리기·정리·재초기화 성공. 수령 처리로 실제 화물5개 적재/배송 시작 성공.
- 단위 검사의 창 없는 RoadMap 경로는 ‘렌더러가 없습니다’ 폴백 로그를 출력하지만 검사 자체는 통과했다. 실제 SDL 검증에서는 해당 오류/이미지 폴백이 없었다.
- 기존 Python 캐시는 보존했고 실행 명령에 -B를 사용했다.

## 사전 생성 캐시·성능

관련 소스/설정 변경에 맞춰25개 캐시를 새 해시로 생성하고 assets/ground/title_match_v2를 갱신했다. 새로운 캐시가 맞는 경우 실제 첫 시작에서 합성하지 않는다.

| 항목 | 개선 전 | 개선 후 |
|---|---:|---:|
| play_mode.init 최초 |0.507초|**0.497초**|
| 같은 프로세스 재시작 |0.504초|**0.500초**|
| 지면 준비 최초/재시작 |0.09/0.09초|0.09/0.09초|

| 실제 압축 지면 파일 합계 |642,899바이트|668,864바이트|

압축 파일 증가25,965바이트(약25.4KiB), 추가 GPU 텍스처/프레임당 출력0개/0회(코드 기준)다. 메모리상의 지면 크기·개수는 동일하다. 시간은 개별 실측이며 평균/FPS가 아니고, 프로세스 실행·import·타이틀 대기를 제외한다.

개발용 강제 생성에는17.648초가 걸렸고 이 결과를 동봉했다. 일치하는 캐시가 없으면 기존 재생성 경로로 복구하므로 변경 후 캐시 갱신이 필요하다. 기존 EXE는 재빌드하지 않았다.
