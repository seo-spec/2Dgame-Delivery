# 지면 연결과 외곽 마감 수정

2026-11-28. 사용자 첨부 화면의 좁아지는 포장 연결부·독립된 녹지 띠를 기준으로 기존 출발지와 배송 구역3곳의 표시 지면 구성을 다시 점검했다. 이전 마감 점검에서 이런 조형상의 어색함을 충분히 짚지 못했다. 이번에는 실제 지면 합성 구조와 배치를 수정했다. 커밋하지 않았다.

## 원인과 수정

- 기존에는 사각형마다 별도로 외곽을 혼합했다. 같은 재질이 겹쳐도 내부 경계가 남아 포장이 조각처럼 보일 수 있었다. 이제 최종 재질 영역을 먼저 합친 뒤 한 번만 출력 색을 계산한다. 내부 접점과 기존 보도 쪽에 잔디색 테두리를 만들지 않는다.
- 출발지 휴식 공간은 벤치 쪽과 나무 쪽을 좁은 길로 연결한 형태였다. 이를 (524,524)~(976,678)의 연속 포장으로 정리해 기존 보도와 맞닿게 했다. 도로/보도 마스크는 그대로 보호한다.
- 얇고 둥근 녹지 막대가 포장 위/주변에 따로 놓여 띠처럼 떠 보였다. 출발지·주택·상점의 기능 없는 표시용 띠들을 제거했다. 실제 화분·나무·충돌 객체를 삭제한 것은 아니다.
- 나무 밑의 큰 둥근 사각형 녹지는 수관 크기에 맞춘 타원형으로 바꾸고 가장자리6px에서 바탕 포장으로 부드럽게 섞는다. 기존 나무 위치/표시 크기/충돌은 유지한다.
- 카페와 서비스 바닥 사이의4px 틈, 주택/상점 앞 포장 시작선, 북쪽 상점 작업 공간의 들쭉날쭉한 시작선을 정리했다. 상호작용 주변 quiet 마스크를 덮지 않는다.

기존4개 적용 범위 안에서만 수정했다. 재질 패턴은 계속 월드2px 기준으로 고정한다. 건물·소품·고객·차량·HUD·도로/충돌/수령/배송 조건과 입력은 변경하지 않았다. 원본/v1/v2 PNG는 보존했다.

## 수정 파일

- game/world/neighborhood_finish.py: 재질 영역 합치기, 내부 테두리 제거, 타원형 녹지/가장자리 혼합.
- data/maps/sample_map.json: 연결 폭·보도 접점 조정, 표시용 녹지 띠 제거.
- tests/test_neighborhood_finish.py: 포장 합침과 녹지 혼합 회귀 검사2개 추가.
- assets/ground/title_match_v2: 갱신한25개 사전 생성 캐시/manifest.
- 이 문서와 이전 결과의 후속 링크. 새 실행 캡처를 문서/답변에 첨부하지 않았다.

## 검증

- 자동 검사32개 통과(기존30+새2). 두 포장 조각을 합친 결과가 하나의 포장과 같고 내부 테두리가 생기지 않는지, 타원 녹지가 바탕으로 부드럽게 섞이며 알파가 유지되는지 확인했다.
- 기존 맵과 비교해 표시용 neighborhood/neighborhoods 외의 모든 데이터가 동일하다.
- 지면25개 RGBA를 비교해 기존4개 적용 범위 밖 픽셀이 모두 동일하다. 실제로 내용이 달라진 캐시는8개다.
- 실제 SDL 초기화·그리기·갱신·재시작, 수령 후/임박5초/지각5초/실제 배송 완료 검증이 통과했다.
- 내부 확인에서 출발지의 좁은 연결부와 떠 보이던 띠가 사라지고 포장이 연속된 것을 확인했다. 검토용 임시 화면2개만 .tmp에 남겼고 새 문서 이미지/비교 보드로 만들지 않았다.
- 실행은 -B로 수행해 기존 Python 캐시를 쓰거나 정리하지 않았다.

개별 실측이며 평균/FPS가 아니다. 프로세스 시작·타이틀 대기를 제외한 play_mode.init 시간이다. 개발 중 강제 생성16.939초의 결과를 동봉해 실제 첫 시작에서 다시 생성하지 않는다. GPU 텍스처/프레임당 출력 수는 그대로다. 재질 영역 버퍼는 초기화 때만 사용하는 임시 CPU 데이터이며 매 프레임 생성하지 않는다.

## 남은 수동 확인

출발지 휴식 공간과 세 배송 구역을 이동하며 포장 폭·보도 접점·나무 밑 경계의 최종 미술 만족도를 확인한다. 다른 카메라 위치/화면 모드, 장시간 주행 중 안내 겹침, 배포 EXE는 별도 확인이 필요하다. 기존 EXE 재빌드는 하지 않았다.
