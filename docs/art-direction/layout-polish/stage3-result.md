## 결과와 변경 범위

이번에 확인한 표본 화면에서는 추가 환경 수정이 필요한 불일치를 찾지 못했다. 따라서 게임 코드·맵·이미지·사전 생성 캐시는 변경하지 않고 검증 자료만 추가했다. 새 구역·장식·기능·애니메이션·충돌은 추가하지 않았다. 차량·고객·HUD·입력·배송 규칙도 그대로다.

- [상태별 비교](states.svg): 대상3곳 × 수령 전/수령 후/임박/지각/완료. 이미지를 누르면 원본1280×720을 연다.
- [배송 동선 주변 비교](route.svg): 출발지→북쪽 연결로/교차로→파란 주택→북쪽 상점→동쪽 연결 교차로→동쪽 상점.
- 각 PNG는 실제 SDL_RenderReadPixels 결과다. 생성 시안이나 이미지 편집 결과가 아니다.

## 점검 방법과 한계

기존 Windows Python3.13·Pico2D/SDL,1280×720, sync=True로 실행했다. 사용자 컴퓨터에 키보드/마우스 입력을 주입하지 않도록 숨긴 실제 SDL 창을 사용했다.

테스트 도구 .tmp/verify_layout_polish.py에서 대상3개를 배송지로 고정하고 난수 시드를 맞췄다. 실제 게임의 무작위 선정 코드는 바꾸지 않았다. 수령은 기존 수령 처리 경로로 화물5개를 적재해 시작했다.

상태 표본은 테스트 프로세스에서 elapsed_time을0, 대상 마감5초 전, 마감5초 후로 설정해 만들었다. 만족/보통/불만과 실제 배송 가능 대상을 assert로 확인했고, 완료는 실제 try_deliver로 지정 화물을 배송한 뒤 확인했다. 게임 시간을 연속으로 진행한 장시간 플레이가 아니며 대상별 시간 설정은 서로 독립적인 시나리오다. 완료된 앞 배송지 정보는 다음 표본에도 남는다.

경로 화면은 해당 위치로 카메라를 옮긴 표본이다. 출발지에서 끝까지 차량을 연속 조작한 주행 검증을 뜻하지 않는다. 중간 경로 표본에서는 차량이 화면 밖에 있으며, 대상별 상태 표본에서는 차량을 실제 배송 구역 안에 두고 확인했다.

## 연결·가독성 확인

| 항목 | 확인 결과 |
|---|---|
| 연결로/교차로 | 확인한 북쪽·동쪽 연결로에서 도로/보도와 월드 재질이 이어지고 새 검은 띠나 뚜렷한 캐시 틈은 보이지 않음 |
| 주택 입구 | 작은 마당·기존 남쪽 문턱·진입부가 연결됨. 기존 배송 공간은 그대로 비워져 있음 |
| 북쪽 상점 | 벽돌/서비스 바닥과 나무 주변 녹지가 구분됨. 기존 입구/배송 공간 유지 |
| 동쪽 상점 | 서비스 앞마당·정류장 포장과 기존 입구가 이어짐. 우편함/정류장/분리수거함의 위치 유지 |
| 수령 전 | 고객/미배송 느낌표가 숨겨지고 기존 수령 안내 유지 |
| 수령 후 | 고객·노란 !·차량·배송 가능 안내를 함께 읽을 수 있음 |
| 임박5초 | 실제 기분 '보통'. 우측 임박 기호/문구와 고객 표시를 구분할 수 있음 |
| 지각5초 | 실제 기분 '불만'. 초과시간/지각 강조와 고객/조작 안내를 구분할 수 있음 |
| 완료 | 실제 배송 후 !와 배송 입력 안내가 사라지고 고객 옆 체크·완료 문구·화물 완료가 표시됨 |

상호작용 배너는 기존대로 건물 지붕/입구의 일부 위를 지날 수 있다. 확인한 표본에서 고객·!·차량은 가리지 않았고, 완료 후 배너가 사라지면 입구 연결을 볼 수 있다. 사용자 지시대로 HUD 위치를 변경하지 않았다. 모든 카메라/차량 위치에서 가림이 없다는 보장은 아니며 아래 수동 확인을 남긴다.

기존 역할을 읽는 데 필요한 재질 대비는 확인했지만, 공간이 충분히 풍성한지에 대한 미술적 만족도는 별도 사용자 판단이다. 이번 단계에 새로운 밀도 확장이나 장식은 넣지 않았다.

## 자동 검사와 실측

- py -3.13 -B -m unittest discover -s tests -q: **30개 통과**,0.113초.
- 실제 SDL 초기화·갱신·그리기·종료/재초기화 통과.
- 대상3곳의 만족/보통/불만, 배송 가능 대상, 실제 완료 후 대상 제외 검증 통과.
- 출발지 시작 화면 PNG는 이전 단계와 SHA-256이 동일했다.
- 창 없는 단위 검사에 출력되는 ‘렌더러가 없습니다’는 그 검사의 폴백 로그다. 실제 SDL 실행에서는 해당 오류/이미지 폴백이 없었다.
- -B로 실행했으며 기존 Python 캐시를 정리하거나 새로 쓰지 않았다.

| 구간 | play_mode.init | 지면 준비 | 캐시 |
|---|---:|---:|---|
| 빈 로컬 캐시로 최초 시작 |**0.501초**|0.09초|25/25, 재생성0 |
| 같은 프로세스 재시작 |**0.492초**|0.09초|25/25, 재생성0 |

각 값은 한 번의 실측이며 평균/FPS가 아니다. Python 실행·import·타이틀 대기를 제외한 플레이 초기화 시간이다. 사전 생성 지면25개 압축 합계는 기존과 같은668,864바이트다. 게임/지면 코드와 자산이 바뀌지 않아 캐시를 다시 만들지 않았다. 추가 텍스처·월드 출력은0개/0회다.
