# 출발지 한 화면 미술 방향과 적용 계획

## 결과물과 검토 상태

- `preview.svg`: 최종 검토 화면. 1280×720, 플레이 1000×720 + 배송 패널 280×720. 같은 폴더의 PNG를 참조하므로 함께 보관한다.
- `concept-v2.png`: 내장 image_gen 도구로 제작한 최종 방향 시안. 생성 원본은 1672×941이며, SVG에서 플레이/패널을 각각 배치해 실제 화면 비율로 표시한다.
- `concept-v1.png`: 최초 비교안. 상점 입면과 넓은 패널이 강하게 나타나 최종안에서 줄였다.
- `generation-prompts.txt`: 제작에 사용한 프롬프트와 참조 자산.
- 게임 코드와 실제 플레이 자산은 수정하지 않았다. 게임 실행·자동 테스트·커밋도 수행하지 않았다.
- **최신 실행 화면은 미확인이다.** 아래 현황은 코드와 원본 자산을 읽고 확인한 사실이며, 실제 합성 결과와 프레임 성능을 측정한 결과가 아니다.

| 건물·나무·차량 | `building_sample.png`, `building_delivery_depot.png`, `tree.png`, `motorcycle/motorcycle_16.png`: 부드러운 색 변화와 높은 원본 디테일 | 축소 시 디테일이 흐려지고 도트풍 바닥·글자와 표현 차이가 커질 수 있음 |

| 명암 | 좌상단에서 빛, 우하단으로 짧은 접지 음영. 자산군당 기본색+밝은면+어두운면 3~4단계. 넓은 부드러운 그라데이션은 줄임 |

### 가독성 기준

- 차량과 도로는 명도뿐 아니라 민트 헬멧·주황 상자·짙은 외곽선으로 구분. 환경에 같은 크기의 민트/주황 강조점을 남발하지 않는다.
- 수령/배송 마커는 2~3px 경계선 + 상자/화살표 기호 + 짧은 문구로 표시. 고밀도 바닥 질감과 소품은 마커 주변에 두지 않는다.
- 본문 텍스트 대비는 4.5:1 이상, 중요한 아이콘과 바의 경계는 3:1 이상을 설계 목표로 삼는다. 위 팔레트 모든 조합이 통과했다고 검증한 것은 아니다.
- 지각은 붉은색에 `!`와 초과시간을 함께 표시. 화물 상태도 내구 바와 수치·적재/완료/파손 문구를 병기한다.
- 100% 화면에서 읽힘을 먼저 보고, 50% 축소에서는 차량·도로·목적지와 위험 기호가 구분되는지 검토한다.

## HUD 정보 보존 및 시안의 한계

| 기존 정보 | 최종 구현에서의 처리 |
|---|---|
| 전체 남은 시간 | 상단에서 가장 큰 숫자로 표시 |
| 배송 완료 수 / 전체 수 | 상단 `0/5` 유지. **최종 생성 그림에서는 이 수치가 빠져 있어 구현 시 반드시 복원** |
| 현재 수익 / 목표 수익 / 진행 상태 | 상단 유지. 시안은 상태 문구가 중복되므로 실제 구현에서는 한 곳에만 표시 |
| 화물 종류 / 내구 수치와 바 / 적재·완료·파손 | 하단 5카드에 유지 |
| 배송지별 마감 / 초과 시간 / 고객 기분 / 화물 종류 | 우측 5카드에 유지. 가장 급한 곳은 테두리+기호로 강조하되 순서는 임의로 바꾸지 않음 |
| 수령·배송·복귀 안내 / 목적지 방향 | 플레이 영역의 기존 안전 영역에 짧게 표시. 그림에서 빠진 상태도 기능 삭제 대상이 아님 |
| 미니맵 / 운석 예고·차단·벌금 안내 | 기존 실제 사건 데이터 유지. 생성 그림의 범례는 표시 스타일 예시일 뿐이며 기존 알림 내용을 대체하지 않음 |
| 실패·성공·일시정지·재시작 | 기존 동작과 정보 유지. 이번 이미지에 모두 그리지는 않음 |

**시안의 모든 글자·수치·내구도·적재 상태·상품명은 구현 전 예시다.** `배송 중`인데 `미적재`로 표시된 생성 이미지의 불일치도 실제 UI에서는 허용하지 않는다. 최종 마감 값과 화물 종류는 현재 무작위 선택/마감 배정 로직에서 읽어야 한다. 이미지의 고정된 A~E 시간은 실제 고정 순서를 뜻하지 않는다. 첫 시안의 주소·주문 알림·운석 카운트다운은 현행 기능이 아니며 구현 대상으로 삼지 않는다.

생성 이미지는 완성된 도트 타일셋이 아니다. 픽셀 크기·좌표·외곽선에는 편차가 있고 나무에 타이틀식 옆면이 남아 있다. 실제 제작에서는 수관 위주 탑다운으로 교정하고, 생성 그림을 그대로 통짜 플레이 배경으로 사용하지 않는다.

## 현재와 달라지는 부분

- 타이틀의 청록·주황·크림 색을 인게임 지면/지붕/차량/HUD로 연결한다.
- 보도→작업 마당→배달소의 재질과 접지 경계를 연결하고, 풀은 저대비 덩어리로 정리한다.
- 소품을 주행로 밖의 건물 가장자리·대기 공간에만 배치해 쓰임새를 드러낸다.
- 밝은 배송 패널을 상하단과 같은 어두운 계열로 통일하고 시간·위험 상태의 대비를 높인다.
- 움직임을 늘려 해결하기보다 정지 화면에서의 크기·시점·색상 일치를 먼저 완료한다.

## 재사용과 교체

| 재사용 | 교체·재제작 또는 조정 |
|---|---|
| 화면/카메라 크기, 맵 좌표, 도로 연결, 충돌, 수령·배송 구역 | 새 도트풍 지면 타일과 경계 표현 |
| 배달소의 주황 지붕·상자 표식, 차량별 색과 디자인 | 배달소·출발 화면 건물의 픽셀 밀도/명암 정리 |
| 기존 소품의 배치 좌표와 충돌 | 선정 구역의 나무·벤치·우편함·분리수거함 그래픽 |
| Galmuri 폰트, 배송/내구/마감/위험 데이터 | HUD 패널·카드·아이콘 외곽선과 간격 |
| 정적 합성/이미지 공유/화면 밖 출력 생략 구조 | 차량/마커/화물 아이콘은 임시 재사용 후 지면 적용 결과를 보고 같은 도트 밀도로 순차 교체 |

새 장식은 기본적으로 비충돌 바닥 장식으로 제한한다. 충돌할 것처럼 보이는 대형 소품은 현재 장애물 위치 안에서 대체하거나 별도의 게임플레이 변경 단계로 분리한다.

## 단계별 적용 계획과 완료 기준

1. **화면 기준 합의**: 이 시안의 팔레트/픽셀 밀도/탑다운 시점/패널 스타일을 검토한다. 완료 기준: 기준 화면과 예외 목록 확정. 코드 변경 없음.
2. **지면 통일**: 출발 화면 범위의 잔디·도로·연석·작업 마당만 도트 밀도를 맞춘다. 완료 기준: 타일 이음새가 없고 기존 도로 판정 및 마커 대비 유지. 건물/HUD는 아직 유지한다.
3. **배달소 1개 교체**: 원본 보존, 새 자산을 기존320×320 크기와 위치에 연결한다. 완료 기준: 지붕 시점·수령 구역·기존 충돌이 맞고 지면 위에 자연스럽게 놓임. 기존 환기구/조명 부착 위치도 새 이미지에 맞춰 조정한다.
4. **주변 자산 한 묶음**: 화면에 걸리는 집1종, 나무1종, 벤치·우편함·분리수거함을 같은 기준으로 제작한다. 완료 기준: 크기와 투명 여백 유지, 마커/주행로 침범 없음. 나무 애니메이션의 효과·유지는 이 단계에서 다시 판단한다.
5. **HUD 상단과 오른쪽 패널**: 기존 데이터/기능을 유지하고 타이머/배송 수/수익/상태 및 5개 배송 카드를 순서대로 변경한다. 완료 기준: 긴 한글·지각·완료 상태가 넘치지 않고 위험 표시가 색에만 의존하지 않음.
6. **화물 카드·마커·차량 정리**: 하단5카드, 아이콘, 마커, 차량을 각각 작은 커밋 단위로 맞춘다. 완료 기준: 5종 화물과 모든 상태의 가독성, 방향별 차량 크기/충돌 유지.
7. **기준 화면 확인 후 확대**: 기존 구역 바깥으로 자산을 확장한다. 완료 기준: 구역 경계의 스타일 차이 해소, 성능 예산 확인. 실행 검증은 사용자가 허용한 시점에 진행한다.

### 성능 계획 — 예상이며 미측정

- 바닥의 얼룩·잔디 점·작은 틈·장식은 기존 정적 레이어 또는 청크에 초기화 시 합성한다. 작은 풀 한 포기마다 객체를 만들지 않는다.
- 현재900×1300 RGBA 지면은 약4.46MiB이며 최종 코드에서 추가 텍스처를 겹쳐 늘리기보다 교체/통합을 우선한다.
- 넓은 구역은 512×512 RGBA 청크(개당1MiB)를 후보로 삼고 카메라와 겹치는 청크만 그린다. 기존 단일 합성보다 유리한지는 후속 측정으로 결정한다.
- 건물·나무·소품은 종류별 공유 텍스처/아틀라스로 준비한다. 회전 애니메이션이나 프레임별 이미지 생성은 필요하지 않다.
- 정적 HUD 테두리는 캐시하고 숫자·상태만 갱신한다. 매 프레임 파일 로딩이나 정적 레이아웃 재생성을 하지 않는다.
- 미술 교체 전후 같은 카메라에서 출력 횟수·텍스처 메모리·프레임 시간을 후속 단계에 비교한다. 이번 단계에서는 측정하지 않았다.

## 다음 구현 작업

먼저 단계2의 **출발 화면 지면 도트 밀도 통일**만 적용한다. 이 문서와 시안을 기준으로 지면을 맞춘 뒤 배달소1개를 교체한다. HUD와 나무 움직임을 동시에 고치지 않아 각 변경의 효과를 비교할 수 있게 한다.
