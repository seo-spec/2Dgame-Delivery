# 조작·상태 안내 배너 정리

- 기존 수령/배송 조작 안내는 하단 같은 위치에서 일반 수령 안내와 겹칠 수 있었고, 벌금 안내는 별도 상단 위치를 사용했다.
- 공통 `NoticeStack`으로 청회색 바탕·도트 테두리·기존 Galmuri 캐시를 공유한다. 조작/상태/경고/실패를 제목·색상으로 구분한다.
- 우선순위: 실패100 → 벌금90 → 재시작80 → 수령/배송 조작70 → 일반 수령/복귀 상태20. 같은 안내는 한 프레임에서 중복하지 않는다. 조작 안내가 있으면 일반 상태 안내는 생략한다.
- 긴 문장은 글자 단위 예상 폭으로 줄을 나누고 기존 `max_width`를 함께 사용해 배너 밖으로 넘치지 않게 한다. 문장 내용은 임의로 잘라내지 않는다.
- 상단/하단 패널 사이에서 폭520/400/300 후보와 중앙/좌우 위치를 탐색한다. 하단 카드 상단120보다12px 위부터 시작하고 상단78px 영역 아래로 제한한다.
- 미니맵·운석 안내 예약 영역, 오토바이, 고객 몸체와 머리 위 느낌표, 집 이름, 성공 결과창, 디버그 도구 예약 영역을 피한다. 배너끼리도 겹치지 않게 한다.
- 모든 후보가 가려지면 해당 안내는 그 프레임에서 생략한다. 정해진 표시 시간을 늘리거나 사건을 다시 발생시키지는 않는다. 기본 해상도에서 여러 상황을 수동 확인해야 한다.
- 차체 위 배송 느낌표 호출은 공통 조작 배너로 대체했다. 고객의 미배송 느낌표와 수령 후 등장 조건은 그대로다.
- 수령 안내는 기존 `WAITING` 상태와 `in_pickup_zone()`, 배송 안내는 입력과 같은 `current_delivery_target()`를 사용한다. 복귀는 기존 자동 판정을 유지하며 불필요한 Space 안내를 추가하지 않는다.
- 벌금 금액·표시 시간·배송/충돌/화물 계산·월드·상단/하단/우측 패널은 변경하지 않았다. 일시정지 중에는 배너를 덧그리지 않는다.
- 기존18px/16px 텍스트 캐시를 빌리고 파일/폰트/패널 이미지를 매 프레임 생성·로드하지 않는다. 새로운 문자열/색 조합은 기존 캐시 정책에 따른다.
- 실행 테스트·자동 테스트·커밋은 수행하지 않았다. 실제 줄 높이, 움직일 때 배너 위치 변화, 혼잡 상황에서의 생략 빈도는 미확인이다.

## 수동 확인

- 구역 밖에서는 일반 수령 안내, 구역 안에서는 `Space: 화물 수령`이 중복 없이 나오는지.
- 배송 가능한 집에서만 해당 집의 Space 안내가 나오고 완료/기한 경계와 일치하는지.
- 벌금과 배송 안내가 동시에 발생할 때 서로 겹치지 않는지.
- 고객 느낌표·차체·미니맵·화물 카드·운석 안내를 가리지 않는지.
- 복귀/실패 사유/재시작 안내와 긴 문구가 정상인지.
- 일시정지/재개/재시작 후 이전 프레임의 안내가 남지 않는지.
