# 맵 북쪽 끝 지면 확장

## 적용 범위

x0~3600, y2100~2700을 폭600×높이600의 정적 캐시 여섯 개로 나눴다. x 범위는 0~600, 600~1200, 1200~1800, 1800~2400, 2400~3000, 3000~3600이다. 기존 아홉 구역과 합치면 전체 적용 범위는 (0,200)~(3600,2700)의 빈틈없는 직사각형이다. 남쪽 y0~200은 이번 범위에 포함하지 않는다.

## 재사용과 경계

- sample_map.json의 road_finish.extensions에 여섯 범위만 추가했다. 재질 생성·렌더링 코드와 이미지 자산은 변경하지 않았다.
- 기존 월드 좌표 기반 잔디·아스팔트·보도 줄눈·연석·차선과 배송 구역 주변 quiet 마스크를 사용한다.
- 기존 RoadMap이 전체 범위의 외곽을 계산하므로 y2100은 내부 경계가 되어 페이드하지 않는다. y2700과 x0/x3600은 실제 월드 끝이므로 fade_edges가 꺼진다. 남쪽 y200에는 기존 96px 페이드를 유지한다.
- 기존 2px 합성 여백과 clip_draw를 재사용해 이웃 연석/음영을 읽되 캐시 가장자리가 중복 출력되지 않게 한다.
- 초기화 시 각각 합성·업로드한 텍스처를 보관하고, 화면 밖인 구역은 출력하지 않는다. 매 프레임 이미지 생성·파일 로딩은 없다.
- 건물·소품·고객·HUD·도로 형상·충돌·배송 구역·입력 조건은 수정하지 않았다.

## 메모리와 출력 예상

각 캐시의 표시 크기는 600×600, 저장 크기는 사방 2px 여백을 포함한 604×604다. RGBA 4바이트 기준 한 장 1,459,264바이트, 여섯 장 합계 8,755,584바이트(약 8.35MiB)다. 기존 텍스처 크기는 그대로이며 전체 재질 텍스처 15개의 합계는 36,373,760바이트(약 34.69MiB)다. 진입부·다른 이미지·초기화 중 임시 CPU 버퍼는 별도다. GPU 실측값이 아닌 환산값이다.

실제 플레이 영역 너비1000px은 폭600px인 구역에 최대 3개 걸칠 수 있다. 따라서 현재 카메라 기준 추가 출력은 최대 3회, 새 구역이 전부 화면 밖이면 0회로 예상한다. 화면/카메라 크기가 바뀌면 상한도 달라진다. 추가된 여섯 텍스처를 모두 매 프레임 출력하지 않는다. 초기화 시간과 프레임 성능은 실행 측정하지 않았다.

## 수동 확인

- y2100을 넘을 때 풀·도로·보도에 밝은 줄·어두운 띠·무늬 단절이 없는지.
- x600/1200/1800/2400/3000의 새 캐시 경계와 y2100 교차점에서 연석과 차선이 이어지는지.
- 북쪽 y2700과 좌우 월드 끝에서 불필요한 페이드나 바닥색 띠가 없는지.
- 북쪽 배송 후보 건물의 고객·느낌표·마커가 잘 보이는지.
- 기존 건물/소품 충돌·배송 입력·HUD가 유지되는지.
- 카메라 이동·재시작 후 누락/잘림이 없는지, 초기화 시간이 허용 가능한지.

실행 테스트와 커밋은 하지 않았다. 실제 합성 화면·프레임 성능·초기화 시간과 실패 폴백 실행 결과는 미확인이다.
