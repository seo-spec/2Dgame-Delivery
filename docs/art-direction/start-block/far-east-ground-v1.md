# 동쪽 배송 경로 지면 확장

## 적용 범위와 캐시

요청 범위 x2400~3000과 x3000~3600, 공통 y200~2100을 각각 y1200에서 나눴다.

| 구역 | 표시 범위 (left,bottom,right,top) | 저장 크기 (2px 여백 포함) | RGBA 예상 |
|---|---|---|---:|
| 동쪽 1 남쪽 | (2400,200,3000,1200) | 604×1004 | 2,425,664바이트 |
| 동쪽 1 북쪽 | (2400,1200,3000,2100) | 604×904 | 2,184,064바이트 |
| 동쪽 2 남쪽 | (3000,200,3600,1200) | 604×1004 | 2,425,664바이트 |
| 동쪽 2 북쪽 | (3000,1200,3600,2100) | 604×904 | 2,184,064바이트 |

추가 합계는 9,219,456바이트(약 8.79MiB)다. 기존 5개와 합친 재질 텍스처 9개는 27,618,176바이트(약 26.34MiB)이며 진입부·다른 이미지·초기화 중 임시 CPU 버퍼는 별도다. RGBA 4바이트/픽셀 환산값이며 GPU 실측값은 아니다.

## 기존 구조 재사용

- road_finish.extensions에 네 범위를 추가했다. 기존 재질 생성·초기화 업로드·구역별 캐시·화면 밖 출력 생략을 그대로 사용한다. 매 프레임 생성·파일 로딩은 없다.
- 큰 600×1900 텍스처 두 장 대신 네 장으로 나눠 개별 텍스처와 초기화 중 단일 구역 버퍼 크기를 줄였다. 분할 때문에 합계 메모리가 줄어드는 것은 아니며 합성 여백이 조금 늘어난다.
- 전체 범위는 (0,200)~(3600,2100)의 빈틈없는 직사각형이다. 기존 월드 좌표 기반 풀·도로 자국·보도 줄눈과 페이드를 재사용하므로 x2400·x3000·y1200 내부 경계에 별도 페이드는 없다.
- 기존 2px 합성 여백과 clip_draw로 연석/음영의 이웃 픽셀을 읽되 여백을 중복 출력하지 않는다. 기존 작은 진입부는 지면 재질 다음 출력 순서를 유지한다.
- 오른쪽 x3600은 실제 월드 끝이므로 기존 fade_edges 규칙에 따라 페이드하지 않는다. 위아래 y200/y2100에는 기존 96px 페이드를 유지한다.
- 추가 출력은 새 네 캐시가 모두 화면에 걸칠 때 최대 4회, 전부 화면 밖이면 0회다. 전체 텍스처 9개를 매 프레임 모두 출력하지 않고 각각 범위를 검사한다. 실측 출력 횟수/프레임 성능은 미확인이다.
- 건물·소품·고객·HUD·도로 연결·형상·충돌·배송 구역·입력 조건은 수정하지 않았다. 맵 변경은 지면 표시 범위 네 개 추가뿐이다.

## 수동 확인

- x2400의 기존 구역 연결부에서 밝은 줄·어두운 띠·풀 패턴 단절이 없는지.
- x3000과 y1200, 두 경계의 교차점에서 보도·연석·차선이 자연스럽게 이어지는지.
- 분수 (2850,1950), 카페 (2850,1050), 동쪽 배송 후보 건물 주변의 고객/마커가 잘 보이는지.
- 월드 오른쪽 x3600에서 불필요한 바닥색 띠나 화면 밖 잘림이 없는지.
- 기존 충돌·배송 입력·고객·소품·HUD가 유지되는지.
- 카메라 이동·재시작 후 누락이 없는지, 초기 로딩 시간이 허용 가능한지.

실행 테스트와 커밋은 하지 않았다. 실제 합성 화면·프레임 성능·초기화 시간과 실패 폴백 실행 결과는 미확인이다.
