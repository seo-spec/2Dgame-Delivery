# 기본 배송 주택 B 입구 연결

- 대상: `delivery_house_b`, 월드 (1450,1050), 표시 280×280.
- 원본과 입구 PNG를 직접 확인했다. 지붕 구도와 투명 여백이 같은 배치를 기준으로 제작된 기존 `building_sample_entrance_pixel_v1.png`를 북쪽 주택과 공유한다. 실제 화면에서 실루엣 정합은 미확인이다.
- 기존 기본 도트 이미지와 입구 이미지의 로드/폴백 캐시를 공유한다. 추가 건물 텍스처는 없다. 입구 이미지 실패 시 공유 도트 주택, 그것도 실패하면 원본을 사용한다.
- 진입부: x1426~1474, y918~976 (48×58). 문턱: x1432~1468, y964~976 (36×12). 북쪽 주택 구성을 (+700,+150)만큼 이동했다.
- 배송 구역 x1360~1540, y840~930과 아래쪽 12px이 겹친다. 위쪽 2px은 충돌 외곽 y974에 겹치며 건물 이미지 아래에 그린다. 고객의 기존 발 위치 (1520,856)는 유지한다.
- 기존 지면 합성 범위 밖이므로 범위를 확장하지 않고 진입부 전용 투명 텍스처를 초기화 시 합성한다. 기존 포장 생성·업로드·화면 밖 출력 생략 코드를 재사용한다. 도로 위 픽셀은 덮지 않는다.
- 추가 RGBA 메모리 예상: 48×58×4 = 11,136바이트(약 10.88KiB). 화면에 보일 때 최대 1회 추가 출력. 실측값이 아니다.
- `road_finish.entry_paths`는 표시 전용이다. `access_paths`, 도로 형상, 충돌, 건물/고객 위치, 배송 구역과 입력 조건은 변경하지 않았다. 다른 건물과 HUD도 유지한다.

## 수동 확인

- 대상 주택과 북쪽 주택의 입구가 표시되고 다른 주택은 유지되는지.
- 대상 문·문턱·진입부가 자연스럽게 연결되고 투명 사각형이나 검은 테두리가 없는지.
- 고객과 느낌표가 가려지지 않는지.
- 기존 충돌과 배송 입력 조건이 유지되고 진입부가 새 도로로 판정되지 않는지.
- 카메라 이동과 재시작 후 이미지/진입부가 정상인지.

실행 테스트와 커밋은 하지 않았다. 실제 합성 화면은 미확인이다.
