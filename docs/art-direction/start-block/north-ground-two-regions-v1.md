# 북쪽 배송 경로 지면 두 구역 확장

## 적용 좌표

| 구역 | 표시 범위 (left,bottom,right,top) | 주변 건물 |
|---|---|---|
| 북서 | (0,1500,1200,2100) | 파란 배송 주택 (750,1650), 카페 (750,1950) |
| 북동 | (1200,1500,2400,2100) | 배송 상점 (1450,1650), 아파트 (1350,1950)/(2250,1950) |

기존 세 구역에 두 구역을 추가했다. 전체 표시 범위는 (0,200)~(2400,2100)이며 다섯 구역이 빈틈없는 직사각형을 이룬다. 배송 대상 선택이나 순서는 변경하지 않았다.

## 기존 합성 구조 재사용

- sample_map.json의 road_finish.extensions에 두 범위만 추가했다. RoadMap이 기존과 같은 초기화 경로로 구역별 텍스처를 생성·보관한다.
- grass_color, asphalt_shade, 보도 포장·연석·차선, 배송 구역 주변 quiet 마스크를 재사용한다. 재질 생성 코드와 이미지 자산은 변경하지 않았다.
- 풀·도로 자국·줄눈·페이드는 월드 좌표 기준이다. y1500 연결부와 x1200 북쪽 내부 경계에는 페이드가 없고, 전체 바깥쪽 y2100/x2400에 기존 96px 페이드를 둔다. 월드 왼쪽 끝은 페이드하지 않는다.
- 기존 2px 합성 여백과 clip_draw 출력을 재사용해 내부 경계에서도 같은 이웃 픽셀을 읽고, 여백이 중복 출력되지 않도록 한다.
- 초기화 후에는 파일 로드·이미지 생성 없이 캐시를 출력한다. 각 구역이 화면 밖이면 출력을 생략한다.
- 기존 진입부 전용 텍스처는 재질 다음에 출력하는 순서를 유지한다. 건물·소품·고객·HUD, 도로 형상·충돌·배송 구역과 조건은 변경하지 않았다.
- 현재 구조의 외곽 페이드는 빈틈없는 직사각형 배치를 전제로 한다. 불연속 구역이나 L자 추가는 별도 외곽 처리 검토가 필요하다.

## 메모리와 출력 예상

| 항목 | 텍스처 크기 (사방 2px 여백 포함) | RGBA 4바이트 환산 |
|---|---|---:|
| 북서 | 1204×604 | 2,908,864바이트 |
| 북동 | 1204×604 | 2,908,864바이트 |

순증가는 5,817,728바이트, 약 5.55MiB다. 기존 세 재질 텍스처는 크기를 변경하지 않는다. 다섯 재질 텍스처 전체는 18,398,720바이트(약 17.55MiB)이며 진입부·다른 이미지·초기화 중 임시 CPU 버퍼는 별도다. GPU 실측값이 아닌 예상값이다.

추가 출력은 북쪽 두 구역이 모두 화면에 걸칠 때 최대 2회, 화면 밖이면 0회다. 전체 재질 텍스처 수는 다섯 개이지만 각 구역을 화면 범위로 걸러 출력한다. 초기화 합성 시간이 늘어날 수 있으며 실행 측정하지 않았다.

## 수동 확인

- y1500을 남북으로 넘을 때 풀·도로·보도에 밝은 줄이나 어두운 띠가 없는지.
- 북쪽 x1200을 넘을 때 무늬·줄눈·연석이 이어지는지.
- x1200/y1500과 x1800/y1500 접점에서 모서리 이음이 자연스러운지.
- (750,1650), (1450,1650)의 문턱·진입부·고객·느낌표가 지면에 가려지지 않는지.
- y2100/x2400의 바깥 경계가 기존 지면으로 자연스럽게 이어지는지.
- 기존 도로·충돌·배송 입력과 건물·소품·HUD가 유지되는지.
- 카메라 이동·재시작 후 누락이나 잘림이 없는지, 초기화 시간이 허용 가능한지.

실행 테스트와 커밋은 하지 않았다. 실제 합성 화면·프레임 성능·초기화 시간은 미확인이다.
