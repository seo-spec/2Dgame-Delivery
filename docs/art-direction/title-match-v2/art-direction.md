## 타이틀의 분위기를 가져오는 방법

1. **큰 면의 연결**: 도로→연석→보도/작업 마당→입구가 한 동네의 재료로 이어지게 한다. 빈 곳마다 장식을 추가하는 대신 지면의 용도를 정리한다.
2. **재료의 크기**: 지붕 이음·돌 블록·목재 판자가 비슷한 화면 단위로 보이게 한다. 모든 원본을 동일 고해상도로 생성한 뒤 축소하는 방식만으로는 일관성이 생기지 않는다.
3. **강조의 절제**: 타이틀의 작은 상점 표식과 잎 밝은 면은 주변 면에 묶인다. 인게임은 거대한 지붕 그림과 강한 노란 잎 면을 줄여 플레이어·!·경고를 남긴다.
4. **접지**: 물체 오른쪽 아래2~6px의 짧은 그림자와 처마 아래2~4px의 어두운 면을 붙인다. 검은 안개/사각형 비네트나 모든 소품의 동일한 큰 원 그림자는 사용하지 않는다.
5. **탑다운 해석**: 타이틀의 길게 보이는 정면/줄기는 지붕 가장자리의 짧은 벽 띠와 수관의 작은 가지 틈으로 축약한다. 북쪽 고정 카메라를 바꾸지 않는다.

### 밀도와 비율

- 세계 좌표1px=화면1px인 현재 카메라에서 **월드 기본 도트는 화면2×2px**. 최종 출력 크기에서 모서리와 블록을 확인한다. 그림자와 작은 얼굴 내부만1px 보조를 허용한다. 최근접 필터를 유지한다.
- 배달소 캔버스320×320, 일반 건물240~320의 기존 표시 크기와 투명 여백 기준을 유지한다. 실제 불투명 외곽은 원본 대비 화면2px 이내 차이를 목표로 검토하고 콜라이더를 다시 맞추는 식으로 해결하지 않는다.
- 배달소 상자 표식은 최종 화면28~36px, 지붕 폭의15% 이내를 시작점으로 한다. 건물마다 간판을 지붕 전체 크기로 붙이지 않는다.
- 나무110px 표준에서는 수관 실루엣90~100px를 기준으로 한다. 기존100/120/130/140 크기는 그대로 유지하므로 도트 밀도 차이를 개별 출력에서 확인한다.
- 벤치110 캔버스 안에 실제 몸체100×45, 쓰레기통32 캔버스/24 몸체, 우편함64/34×32, 화분120/110×36, 정류장230×154/기존 바닥54높이 콜라이더를 유지한다.
- 차량88 캔버스/충돌반경37 유지. 고객72 캔버스와 기존 발 기준 유지, 몸체28~36×44~56px 안에서 표정이 읽히게 후속 검토한다. 캐릭터만 다른 원근으로 확대하지 않는다.
- 차량·고객과 같은 밝은 민트/주황/살색 덩어리를 주변 소품에서 반복하지 않는다. !/수령 안내 주변은 최소24px의 낮은 대비 영역을 확보하되 표시를 피하려고 실제 고객이나 판정 구역을 옮기지 않는다.
- HUD 글자 대비4.5:1, 핵심 기호3:1은 후속 검토 목표다. 이번 단계에서 색상 조합 전체를 측정해 통과했다고 주장하지 않는다. 색만이 아니라 기호·문구로 상태를 유지한다.

| 기존 화분 | (570,650),120 | (320,160), 이번에는 미삭제; 후속 수풀 변형 후보 |
| 북쪽 배송 고객 | 북쪽 집 배송 구역, 기존 발(820,706) | 화면(570,104)지만 실제 표시 조건은 수령 상태 및 해당 집의 선정에 따름 |

**고객 위치 보정:** 북쪽 집 자체는 화면 밖이어도 고객은 배송 구역 때문에 출발 카메라 안에 들어올 수 있다. 화물 수령 전에는 숨김이므로 preview.svg는 수령 대기 상태로 고객을 그리지 않았다. 화물 수령 후에는 해당 집이 실제 배송지로 선정되었을 때 기존 발 위치를 유지한다. asset-board.svg는 고객 외형 참고를 함께 보여 준다. 배달소 고객은 추가하지 않는다.

건물 캔버스와 불투명 지붕 위치는 다르다. 위 캔버스 좌표를 벽·콜라이더 위치로 사용하지 않는다. 출발 시 배달소가 하단에 가려지는 것은 기존 카메라의 결과이며 시안에 지붕 전체를 보이게 하려고 건물을 옮기지 않는다.

## 시안과 적용의 차이

- preview.svg는 **수령 대기 상태**의 정보 예시다. 시간150초,0/5,0/2500원, 화물 미적재를 표시한다. 실제 값은 코드 데이터에서 가져오며 예시 카드A~E는 고정 배송 배정이 아니다.
- 미니맵·운석 예약·수령 안내·5개 화물/배송 카드는 기존 비율을 보여 주는 문서용 도형이다. 새 UI 기능을 구현한 것이 아니다.
- 생성 그림은 색·형태·재료의 기준이고 위치가 정확하지 않다. 최종 그림에서도 가로 도로의 y위치가 목표360보다 위로 치우치며, 수령 기호·벤치/통 크기·카페 지붕 형태·마당 경계에 오차가 있다. 작은 녹지 패치와 벽 이음은 확정 오브젝트가 아니다.
- 첫 안의 잘못된 왼쪽 사거리는 곡선으로 보정했지만, 정확한 원호/차선/횡단보도는 **기존 RoadGeometry 데이터를 우선**한다. 생성 그림의 도로를 이미지로 깔아 충돌/신호 판정을 대체하지 않는다.
- 카페가 그림에서는 기와처럼 표현됐지만 기존 카페의 평지붕·천창 정체성을 우선한다. 시안은 그 지붕 형태 변경까지 승인한 도면이 아니다.
- 현재 화분(570,650)은 최종 그림에서 생략됐다. 이는 실제 삭제가 아니며 다음 단계에서 같은 크기·위치·충돌에 맞는 낮은 수풀/화단으로 재작업한다.
- 동일 카메라의 최신 실행 화면이 없으므로 ‘현재 실행 화면 vs 변경 후 실행 화면’ 비교는 할 수 없다. 이번 비교는 현재 자산 보드 vs 미술 시안이다.

## 4단계 적용 계획과 완료 기준

### 1단계 — 이번 작업

실제 타이틀/현재 자산 비교, 기준 v2, 시안과 배치도, 유지/교체 목록, 예산과 후속 순서를 정리한다. 게임 적용은 하지 않는다. 완료 기준은 산출물이 별도 버전으로 있고 사실·추정·미확인이 구분되는 것이다. **사용자의 시각적 선호 확인은 아직 남아 있다.**

### 2단계 — 출발지 한 화면 완성

범위는 출발 카메라에 보이는 월드 x250~1250,y90~810과 실제 보이는 배달소/카페/소품 외곽이다. 화면 밖 타 건물과 전체 맵에 새 팔레트를 자동 확장하지 않는다. 기존 지면 캐시 경계에서는 월드 좌표 기준 저대비 전환을 사용한다.

순서:
1. palette/ground: 도로·연석·작업 마당·잔디를 기존 정적 합성에 연결. 도로 형상과 판정 데이터 불변.
2. depot-v2: 주황 지붕·작은 상자 표식·북쪽 입구·짧은 그림자 제작. 기존320 캔버스와 콜라이더, 수령 구역 유지. 조명/수증기 부착점만 새 이미지에 맞춘다.
3. start-cafe-v2: 기존 평지붕/천창/차양의 정체성을 유지하며 앞 지면과 연결. (450,150)만 우선 연결하고 공유 원본은 보존한다.
4. foliage/props-v2: (900,600) 나무, (630,580) 벤치, (700,580) 통, (620,330) 우편함, (570,650) 화분을 한 묶음으로 제작/재작업. 화분은 낮은 녹지 대체 후보. 위치·크기·충돌을 유지한다.
5. 조명/접지: 짧은 고정 그림자를 정적 지면 또는 자산 내에 합성. UI와 마커 주변은 조용하게. 새 가로등·상자·차량·배달소 NPC 추가 없음.

제작 자산명은 별도 v2로 한다. 예: depot_title_v2.png, cafe_title_v2.png, tree_title_v2.png, start_props_title_v2.png(공유 아틀라스 후보). 원본과 v1은 보존하며 로드 실패 폴백을 둔다. 고객/차량 원본은 2단계에서 변경하지 않고 기존 동작과 가독성만 유지한다.

완료 기준: 같은 화면에서 재료/광원/도트 단위가 일치하고, 원본 위치/투명 여백/충돌과 입력을 유지한다. 사용자 수동 확인 전에는 실제 정합/성능이 검증됐다고 기록하지 않는다.

### 3단계 — 종류별 공통 자산과 맵 확장

2단계의 실제 확인 후 지면 팔레트와 종류별 건물/소품을 배치 단위로 확대한다. 북/동/남향 배송 구역을 구분하고 공통 지붕을 반대쪽 입구 변형으로 무조건 대체하지 않는다. 같은 종류는 아틀라스/이미지 캐시를 공유한다. 고객·차량 시트는 별도 묶음으로 픽셀 스타일을 맞추되 발/차체 중심·연속 회전·차종 능력치·충돌을 유지한다.

완료 기준: 맵의 같은 종류에서 v1/v2가 의도 없이 섞이지 않고 도로/배송 조건이 동일하다. 공통 자산·입구 변형·폴백을 목록으로 남긴다. 임의의 건물 추가/이동과 새 장식 충돌은 범위 밖이다.

### 4단계 — 마감과 가독성

짧은 그림자 방향, 외곽선 두께, 반복 경계, 고객/느낌표/오토바이 가림, 밤/밝기 효과가 있는 화면과 HUD의 대비를 점검한다. 미수령·수령·임박·지각·파손·완료·복귀/실패 상태를 수동 확인 목록에 포함한다. 장식 강도가 주행 정보보다 크면 줄인다.

완료 기준: 정보 누락/과장된 조명/보이지 않는 충돌이 없고 실제 출력 수·메모리와 화면 검토 결과를 구분해 기록한다. 실행/성능 측정은 사용자가 수행하거나 별도 지시가 있을 때 진행한다.

## 성능·제작 예산 — 설계 목표, 실측 아님

- 기존 RoadFinish의 구역별 합성/화면 밖 생략을 유지한다. 현재 작업 폴더에는 북쪽 끝 확장까지15개 재질 캐시, RGBA 약34.69MiB가 설정되어 있다. 남쪽 y0~200은 이전 기본 바닥이 남아 있으며 이번에 임의 확장하지 않는다.
- 2단계는 기존 재질 캐시 내용을 바꾸는 방향을 우선해 같은 영역에 두 장의 전체 배경을 중복 상주시키지 않는다. 전환용 임시 텍스처가 필요하면 CPU/GPU 각각 별도 예산을 명시한다.
- 새 환경 스프라이트 상주 목표는 **총8MiB 이내**(출발지에서 새로 쓰는 고유 텍스처 기준). 1024×1024 RGBA는4MiB이며 이것을 두 장 쓰면8MiB다. 아틀라스 주변2px 투명 패딩·최근접 필터를 사용하고 최종 화면 도트 단위에 맞는 출력 자산을 준비한다.
- 원본1254² 한 장은 약6MiB다. 최종 화면에 필요한320²는0.39MiB 수준이다. 실제 제작 도구의 출력 크기가 목표와 다르면 원본과 내보내기본을 구분하고 목표를 충족했는지 기록한다. 자동 리사이즈만으로 미술 밀도가 해결됐다고 판단하지 않는다.
- 성공 경로에서 v1/v2를 모두 로드하지 않고 실패 시에만 폴백을 읽는다. 같은 종류의 인스턴스마다 텍스처를 복제하지 않는다.
- 고정 접지 그림자·벽 때·재료 경계는 기존 지면 또는 자산에 합성한다. 모든 잎·벽돌·상자·그림자를 개별 객체로 만들지 않는다.
- 2단계 추가 월드 출력 목표는 기존 대비 **최대2회 이내**다. 그림자 레이어를 늘리기 전에 정적 합성을 우선한다. 현재 총 출력 횟수와 FPS는 측정하지 않았다.
- 기존1px 수관 흔들림 외 새 애니메이션/광원 패스는 이 미술 적용 묶음에 추가하지 않는다. 이미지/마스크 생성은 초기화에만 한다.
- 코드상 출력/메모리 예산과 실제 프레임 시간·초기화 지연·GPU 사용량은 다르다. 이번 단계에는 실행 측정 수치가 없다.

## 남은 확인 항목

- 최신 실제 출발 화면을 같은 카메라와 상태로 비교해야 한다. 현재 시안과 이미지 파일만으로 최신 런타임 가독성을 확정할 수 없다.
- 사용자가 원하는 따뜻함/채도·그림자 강도는 preview.svg와 타이틀을 보고 확인할 항목이다. 이 문서는 구현 기준안이며 취향 승인 완료를 뜻하지 않는다.
- 생성 그림의 위치/카페 형태 오차와 생략된 화분은 실제 적용에 복사하지 않는다. layout-guide.svg와 기존 맵 데이터가 우선이다.
- 폴백 이미지로 돌아갈 때 조명/그림자가 어긋나지 않도록 자산별 부착 메타데이터가 필요하다.
- 전체 월드의 도트 밀도와 새 시트 방향/발 정합, UI 대비/긴 문구, 메모리·출력 예산은 후속 단계별 수동 확인이 필요하다.
