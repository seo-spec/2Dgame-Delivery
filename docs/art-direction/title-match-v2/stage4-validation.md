## 환경·방법

- 기존 Windows Python3.13, Pico2D/SDL의 실제 렌더러,1280×720, sync=True.
- 기존 tests의 도로/신호 검사와 새 tests/test_ground_cache.py를 실행했다.
- .tmp/verify_stage4_live.py로 별도 캐시 폴더를 사용했다. 사용자 .tmp/ground-cache를 삭제하거나 덮어쓰지 않았다.
- 타이틀 초기화/그리기 후 실제 시작 항목의 activate_selection 경로가 play_mode 전환을 예약하는지 확인했다. 사용자가 컴퓨터를 사용 중이어서 이후 OS 키보드·마우스 입력은 주입하지 않았다.
- 플레이 init·실제 SDL 업로드·갱신·그리기·finish·재초기화를 실행했다. 창은 숨겨 렌더링했고 SDL_RenderReadPixels로 화면을 저장해 직접 확인했다. 모의 렌더러가 아니다.
- 측정 구간은 play_mode.init 전체다. Python 프로세스 실행·모듈 import·타이틀 대기·사용자 클릭 지연을 포함한 전체 실행 시간은 아니다.

## 발견한 잔여 병목과 보완

기존 캐시 재사용은 정상이지만 로컬 캐시가 없는 최초 시작의 지면 합성이14초 이상 걸렸다. 현재 맵의 지면21개+진입부4개를 사전 합성해 assets/ground/title_match_v2에 포함했다. 전체25개 압축 데이터는 **614,186바이트(약600KiB)**다. 파일 크기·SHA-256은 manifest.json에 기록했다.

읽기 순서: 유효한 로컬 캐시 → 같은 해시 이름의 동봉 자산 → 기존 합성/로컬 저장. 맵/재질 소스가 바뀌면 해시가 달라져 오래된 자산을 재사용하지 않는다. 소스 줄바꿈은 LF로 정규화해 Windows 체크아웃의 CRLF 차이만으로 캐시가 무효화되지 않게 했다. 현재 지면 RGBA를 재사용하므로 GPU 크기·출력 수·환경 좌표·충돌·배송 판정은 변경하지 않는다.

맵/재질 소스 변경 후에는 사전 생성 파일을 다시 준비해야 한다. 동봉 파일이 없거나 맞지 않으면 안전하게 기존 합성으로 진행하지만 첫 대기가 다시 발생할 수 있다. dist/AlleyDeliveryDemo.exe는 재빌드하지 않았으며 아래 수치는 현재 Python 소스 실행 결과다.

## 자동 검사

실행 명령: py -3.13 -B -m unittest discover -s tests -v

- 기존 도로·신호 판정20개 + 캐시 회귀 검사6개 = **26개 통과**.
- 캐시 검사: 미존재, 저장/복원 일치, 손상된 로컬의 동봉 폴백, 정상 로컬 우선, 잘못된 크기/불완전 압축/후행 데이터 거부, 저장 실패 반환.
- 실제 SDL 검증: 지면25개 준비, 재초기화25/25 재사용, 실제 업데이트·그리기·정리 성공. v2 이미지 폴백/예외 로그 없음.
- 창 없는 도로 단위 검사에서 나오는 ‘렌더러가 없습니다’는 그 검사의 폴백 로그다. 실제 SDL 검증에서는 해당 오류가 발생하지 않았다.
