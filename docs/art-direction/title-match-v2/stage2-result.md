새 PNG는 assets/images/title_match_v2의 *_title_v2.png 7개다. 원본과 v1은 보존한다. stage2-assets.svg에서 실제 제작 자산을 기존 표시 크기로 비교할 수 있다. 이 SVG는 게임 실행 화면이 아니다.

짧은 접촉 음영은 자산의 테두리/아래쪽 면에 포함해 별도 그림자 객체나 매 프레임 그림자 패스를 추가하지 않았다. 실제 배경 위 접지 강도는 실행 미확인이다.

## 지면 적용

- start_scene_art.py에 표시 전용 범위(250,90)~(1250,810)를 정의했다. 밖에서는 기존 색을 그대로 반환하고 안쪽48px에서 부드럽게 전환한다. 전환 영역에 의도하지 않은 색 띠가 보이지 않는지 수동 확인이 필요하다.
- 잔디 #82965A, 아스팔트 #454B49, 보도 #C8BEA5, 작업 마당 #AEA99A, 표시선 #E5D7B9를 기존 무늬/명암에 섞는다. 풀·포장 줄눈·차선의 위치와 도로 형상은 그대로다.
- 기존 RoadFinish 캐시를 재사용하며 매 프레임 팔레트를 계산하지 않는다.
- 기존 재질이 없던 출발 화면 하단 y90~200에 한해 (250,90)~(1250,200)의 작은 캐시를 초기화 때 추가한다. 다른 남쪽 구역 전체를 확장하지 않는다.
- y200 경계에서는 같은 월드 좌표 색을 사용하고 출발 범위 안의 알파를 보완해 기존 외곽 페이드 때문에 새 색이 빠지지 않게 한다.
- 지면과 낮은 수풀을 실제 도로 판정에 추가하지 않는다. 원본 도로·충돌·신호/수령·배송 조건은 바꾸지 않았다.

## 연결과 폴백

- 종류+월드 위치로만 v2를 선택한다. 같은 종류라도 다른 구역의 나무/카페/소품은 기존 공유 v1이다.
- v2는 초기화 때 한 번 준비하고 실패 결과도 캐시한다. 준비 실패 시 v1, 기존 경로에서 v1 실패 시 원본을 사용한다.
- 새 이미지 성공 경로에서는 해당 위치 때문에 v1을 중복 로드하지 않는다. 다른 위치에 필요한 공통 v1은 기존대로 공유한다.
- 생성 PNG는1254×1254이므로 그대로 GPU에 상주시키지 않는다. 기존 PySDL2의 IMG_Load → SDL_BlitScaled → SDL_CreateTextureFromSurface 경로로 최종 표시 크기 텍스처를 만들고, 원본/축소 CPU 면은 바로 해제한다. 최근접 필터와 알파 블렌드를 사용한다. 새 패키지는 설치하지 않았다.
- 필요한 SDL 기능이 없거나 이미지 준비에 실패하면 OSError로 기존 폴백을 사용한다. 실제 SDL 초기화 경로는 실행하지 않았다. 콘솔의 '[출발지 …] v1 사용' 메시지는 폴백 여부를 확인하는 단서다.
- 배달소 v2 조명 기준점은 캔버스 중심에서 (0,+0.375), 크기(0.18,0.045), 환기구는(+0.296,+0.166)이다. 입구·환기구의 원래 위치를 보존한 그림에 맞췄다. v1/원본은 각 기존 부착점을 유지한다. 점멸·수증기 주기와 갱신 방식은 그대로다.
- 위치·표시 크기·충돌·수령/배송 구역·차량·고객·HUD 코드는 변경하지 않았다. 새 NPC·장식·나무 회전도 추가하지 않았다.

## 실제 파일 메타데이터와 예산

PNG 파일의 크기와 알파는 파일을 읽어 확인했다. GPU 수치와 출력 수는 코드 기준 예상이며 실측값이 아니다.

| PNG (모두1254×1254) | 알파128 이상 표본 외곽 (2px 간격) | 초기화 텍스처 | RGBA 예상 |
|---|---|---|---:|
| depot_title_v2.png | (66,68)~(1186,1130) | 320×320 | 409,600바이트 |
| cafe_title_v2.png | (220,254)~(1034,1048) | 280×280 | 313,600바이트 |

| bin_title_v2.png | (176,154)~(1076,1098) | 32×32 | 4,096바이트 |

- PNG7개의 실제 압축 파일 합계는5,488,638바이트다. 모서리 알파는 모두0이다. 원본 PNG를 그대로 디코딩하면 RGBA 합계44,030,448바이트지만 초기화 시 한 장씩 CPU 면을 처리하고 해제한다. CPU 순간 사용량과 GPU 상주량은 다르다.
- 새 환경 텍스처는898,080바이트(약0.86MiB)로 계산상8MiB 목표 이내다. SDL 드라이버의 실제 포맷/정렬/사용량과 로더 실행 결과는 미측정이다.
- 하단 지면 캐시는1004×114(사방2px 포함),457,824바이트(약0.44MiB)다. 새 환경 텍스처와 합치면1,355,904바이트(약1.29MiB)다. 기존 v1이 다른 위치에 계속 필요한 경우의 메모리는 별도다.
- 기존15개 재질 캐시의 크기는 바꾸지 않는다. 팔레트 변환은 초기 합성에만 추가되어 초기 로딩 시간이 늘어날 수 있다.
- 소품/건물 이미지는 각 기존 출력1회를 대체한다. 나무는 기존 수관 출력1회, 배달소 환경 효과도 기존 횟수다. 추가 출력은 하단 지면 캐시가 보일 때 최대1회여서 문서의 최대2회 추가 목표 이내다.
- 최종 파일의 캔버스와 넓은 투명 여백은 유지했지만 불투명 외곽은 완전한 픽셀 일치가 아니다. 특히 배달소 하단은 v1보다 수 px 안쪽이다. 실제 외곽/판정 대응과 축소 후 작은 기호 가독성은 수동 확인 대상으로 둔다. 기준 문서의 화면2px 외곽 차이 목표를 모두 통과했다고 기록하지 않는다.

## 미확인과 수동 확인

1. 시작 시 콘솔에 v2 폴백 메시지가 없는지. 미지원 SDL 기능/이미지 파일 실패 시 정상적으로 v1과 메뉴/게임으로 진행되는지.
2. 출발 화면의 잔디·도로·연석·작업 마당이 자연스럽게 연결되고, x250/x1250/y90/y810 전환부와 y200 캐시 경계에 띠가 없는지.
3. 배달소 작은 표식·얇은 테두리가 읽히고, 북쪽 입구·조명·환기구 수증기가 맞는지.
4. 카페가 평지붕·천창·차양을 유지하고 수풀이 기존 위치에서 낮게 보이는지.
5. 나무의 밝은 면이 과하지 않고 기존 약한 좌우 흔들림만 있는지. 다른 나무·카페·소품이 v1을 유지하는지.
6. 통의 재활용 기호, 우편함의 편지 표식이 실제32/64px 텍스처에서 읽히는지.
7. 기존 충돌·화물 수령·배송·차종별 이동과 고객/!의 상태 조건이 유지되는지.
8. 재시작·카메라 이동·창/전체화면 전환 후 자산 누락·투명 테두리·잘림이 없는지.
9. 로딩 시간·실제 GPU 메모리·프레임 시간은 별도 측정이 필요하며 이번에는 측정하지 않았다.

실행 테스트·자동 테스트·커밋은 하지 않았다. 이미지 개별 형태와 파일 메타데이터·코드 변경 범위만 확인했으며 실제 합성 화면은 미확인이다.
