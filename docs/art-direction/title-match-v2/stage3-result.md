# 3단계 결과 — 공통 자산과 맵 전체 확장

2026-11-28. art-direction.md와 stage2-result.md를 기준으로 환경만 확장했다. 실행·테스트·커밋은 하지 않았다. 아래 메모리·출력 수는 코드 계산에 따른 예상값이며 런타임 측정이 아니다.

## 적용 내용

- 기존 출발지 v2 7종(배달소·카페·나무·벤치·분리수거함·우편함·낮은 화분)을 같은 종류 전체에 공유한다.
- 부족한 9종(기본 주택·파란 주택·상점·아파트, 주택/파란 주택/상점의 입구 변형, 버스 정류장·분수)을 별도 v2 PNG로 추가했다.
- 환경 인스턴스 75개(건물38개, 소품37개)의 기존 위치·표시 크기를 유지한다. 신호등·차량·고객·HUD는 변경하지 않았다.
- 공통 지붕과 배송용 남쪽 입구를 분리했다. 기존 입구가 있는 collision_preview_house, delivery_house_b/c/d/e 다섯 곳만 입구 변형을 쓴다. 북쪽·서쪽 배송 후보를 남쪽 입구로 바꾸지 않는다.
- 기존 배송 진입부 좌표와 합성 순서를 유지한다. 새로운 장식이나 충돌은 추가하지 않았다.
- 원본/v1은 보존하며, 같은 PNG와 준비 크기의 조합을 캐시 키로 사용한다. 실패 결과도 캐시하고 기존 v1→원본 폴백을 사용한다.
- 배달소 조명/수증기와 기존 수관의 작은 좌우 이동을 유지했다. 새 회전·애니메이션은 추가하지 않았다.

## 지면

월드 전체 x0~3600, y0~2700에 v2 팔레트를 사용한다. 잔디 #82965A, 아스팔트 #454B49, 보도 #C8BEA5, 작업 마당 #AEA99A, 표시선 #E5D7B9다. 기존 재질 무늬·월드 좌표 패턴과 도로 마스크를 재사용한다.

남쪽 y0~200을 x600 단위의 6개 정적 캐시로 보완했다. 출발지 전용 작은 중복 캐시는 제거했다. 기존15개와 합쳐21개이며 내부 전환 페이드는 없고 월드 끝에도 새 페이드를 넣지 않았다. 도로 형상·폭·연결·도로 포함 판정은 바꾸지 않는다. 새 포장 바닥은 도로 판정에 포함하지 않는다.

## 파일과 초기화 합성

[자산 보드](stage3-assets.svg)는 PNG를 v1 외곽 기준으로 정규화하고 상점 지붕을 초기 합성한 예상 모습이다. 실행 화면이 아니다. [제작 기록](stage3-generation.md)과 assets/images/title_match_v2/frames.json을 함께 참고한다.

- PNG16개 실제 압축 파일 크기 합계: **13,863,097바이트(약13.22MiB)**. 신규9개는8,374,459바이트다.
- 파란 공통 주택은1388×1133, 정류장은1536×1024, 나머지14개는1254×1254다.
- 생성 캔버스/투명 여백 차이는 frames.json의 source_rect와 reference_rect를 사용해 초기화 때 기존 v1의 외곽에 맞춘다. 원본 PNG를 재가공하지 않는다.
- 상점 두 PNG는 지붕 중앙의 생성 알파 오류가 남아 있다. 초기화 표면에 불투명 청록 지붕 면을 채우고 기존 설비를 다시 합성한다. 원본을 직접 출력한 모습과 게임 준비 텍스처는 이 부분이 다르다. 합성 경계는 수동 확인이 필요하다.
- IMG_Load → CPU 표면 축소/합성 → GPU 텍스처 전송 후 CPU 표면은 해제한다. 매 프레임 이미지 생성·파일 로딩은 없다.
- 최근접 출력과 기존 화면 밖 생략을 유지한다. 나무는 기존 흔들림 범위를 포함해 생략한다.

## 예상 메모리·출력 예산

| 항목 | 코드 기준 예상 |
|---|---:|
| 환경 고유 텍스처16개 RGBA 합계 | 3,807,760바이트 / 약3.63MiB |
| 2단계 환경7개 대비 증가 | 2,909,680바이트 / 약2.77MiB |
| 남쪽 신규 캐시6개(각604×204, 패딩 포함) | 2,957,184바이트 / 약2.82MiB |
| 제거한 출발지 캐시1004×114 | -457,824바이트 |
| 지면 순증가 | 2,499,360바이트 / 약2.38MiB |
| 기본 지면 캐시21개 전체 | 39,330,944바이트 / 약37.51MiB |

환경 텍스처 준비 크기: 배달소320², 카페280², 주택280², 파란 주택300², 상점320², 아파트300², 나무140², 벤치110², 분리수거함32², 우편함64², 화분120², 정류장230×154, 분수230², 입구 변형280²/300²/320². 개별 오브젝트는 기존 표시 크기로 출력한다.

환경 상주 목표8MiB 이내에 해당한다. 지면 수치는 기존 독립 진입부 텍스처4개·기본 도로 텍스처·드라이버 오버헤드를 제외한다. PNG 압축 크기와 GPU RGBA 예산을 혼동하지 않는다. 기존 v1 로드를 피하는 효과가 있어 전체 게임 GPU 증가량을 위 차액만으로 확정할 수 없다.

환경은 기존과 같이 화면 안 인스턴스당 이미지1회다. 별도 그림자 패스는 없다. 1000×720 플레이 영역에서 새 남쪽 캐시는 최대3개가 보일 수 있어 해당 구간 출력이 최대3회 추가된다. 기존 출발지 캐시1회 제거 효과는 카메라 위치에 따라 다르다. FPS·실제 GPU 메모리·로드 시간·최대 총 출력 수는 미측정이다.

## 미확인·수동 확인 항목

1. 출발지에서 북·동·남쪽 월드 끝까지 이동해 y200과 기존 모든 캐시 경계의 색상·줄눈·연석이 이어지는지 확인한다.
2. 공통 주택·카페·아파트·정류장·분수의 실제 크기, 접지, 얇은 윤곽과 타이틀 대비 도트 밀도를 확인한다.
3. 배송 건물5곳의 문/진입부 연결과 방향을 확인한다. 특히 두 상점의 지붕 구멍·직사각형 보완 경계·설비 잘림을 확인한다.
4. 수령 전/후·완료·복귀에서 고객/느낌표/오토바이 가림과 기존 상호작용·충돌·신호 판정이 유지되는지 확인한다.
5. 콘솔의 '[환경 …] v1 사용' 기록과 SDL 초기화 오류 여부를 확인한다. 폴백 검증은 백업 후 PNG1개를 잠시 다른 이름으로 바꿨다가 복원한다.
6. 반복 재시작 시 정상 출력되는지 확인하고, 필요하면 별도 승인된 성능 측정에서 초기화 지연·FPS·GPU 사용량을 측정한다.

현재 화면을 실행하지 않아 위 항목은 전부 미확인이다. 파일/코드 기준 적용 완료와 미술 만족도·런타임 검증 완료를 구분한다.
